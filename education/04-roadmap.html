Plugin Developer · Growth Roadmap

플러그인 개발자로
나아가기 위한 학습 경로

②에서 본 산업의 진화 궤적(빌드타임 → 런타임 → 격리 → 분산)을 개인 학습 순서로 번역한 가이드입니다. 각 단계는 Runnable app/plugins-ext/를 실습장으로 쓰고, "이걸 만들 수 있으면 통과"라는 검증 기준(gate)으로 끝납니다. 책을 읽는 게 아니라 슬롯에 무언가를 꽂아 보면서 올라갑니다.

01 / STAGE LADDER

4단계 성장 사다리

각 레벨은 산업 세대(Gen)와 짝지어집니다. 아래 단계의 gate를 통과해야 다음으로 올라갑니다.

L1 소비자 → 첫 플러그인 ↔ Gen 1 · 빌드타임 등록

배울 것

  • 호스트–플러그인 경계: 매니페스트가 무엇을 선언하는가 (PluginManifest의 slot·position·defaultEnabled)
  • 슬롯/확장점 개념 — 호스트가 자리를 열고 플러그인이 채운다
  • 컴포넌트 등록 흐름: plugin.manifest.ts → registry.ts → 호스트 렌더
  • Vue 컴포넌트 기본기 (props·emit·composable 소비)

Runnable에서 할 것

  • demo-coords 등 기존 데모 플러그인을 그대로 읽고 한 줄씩 추적
  • 새 chip 플러그인 하나를 만들어 8방향 앵커 중 하나에 띄우기
  • registry.ts 배열에 등록 → 화면에 뜨는지 확인
  • position·order를 바꿔 가며 정렬 동작 체감
Gate  빈 매니페스트부터 시작해, 지도 위 원하는 모서리에 내 chip을 띄우고 클릭 동작을 붙일 수 있다.
L2 상태·사이드이펙트를 다루는 플러그인 ↔ Gen 2 · 런타임 결합

배울 것

  • 플러그인이 앱 상태를 읽고 쓰는 흐름 — store·sideeffect 소비 (SidewalkChip 패턴)
  • 단방향 데이터 흐름: 외부 API → sideeffect → store → UI
  • 슬롯 타입별 차이: chip vs sidepanel vs dashboard vs popup
  • 지연 활성화(lazy) 개념과 defineAsyncComponent
  • 플러그인 prefs / on-off 토글 (usePluginPrefs)

Runnable에서 할 것

  • 지도 데이터(시설/경로)를 소비하는 sidepanel 플러그인 제작
  • 토글로 켜고 끄며 store 상태에 반응하는 UI 구현
  • useMapViewer/useMapActions로 지도와 상호작용
  • 플러그인을 동적 import로 바꿔 초기 번들에서 분리
Gate  앱의 실제 상태(경로·시설)에 반응하고, 사용자가 켜고 끌 수 있으며, 필요할 때만 로드되는 패널 플러그인을 만든다.
L3 계약 설계자 — 호스트 API를 만든다 ↔ Gen 2.5 · API 계약 분리

배울 것

  • 플러그인 입장에서 안정적인 공개 표면(plugin context/SDK) 설계
  • 내부 슬라이스 직접 import의 위험 (결합·깨짐) vs 주입형 컨텍스트
  • API 버저닝·하위호환·deprecation 전략 (semver 사고)
  • 확장점을 새로 여는 쪽 설계 — 호스트가 슬롯을 정의하는 법
  • 타입으로 계약 강제하기 (TS 인터페이스·제네릭)

Runnable에서 할 것

  • 플러그인에 넘길 PluginContext 인터페이스 초안 설계 (지도·경로·인증 능력만 노출)
  • 기존 플러그인 1개를 직접 import → context 주입형으로 리팩터링
  • 새로운 슬롯 타입 하나를 호스트에 추가해 보기
  • 계약을 깨는 변경 시 타입 에러로 잡히는지 검증
Gate  플러그인이 앱 내부를 몰라도 동작하도록 공개 컨텍스트를 설계하고, 한 플러그인을 그 위로 옮긴다.
L4 격리·분산·신뢰 — 플랫폼 엔지니어 ↔ Gen 3–4 · 샌드박스/원격

배울 것

  • 실행 격리: iframe·Web Worker·remote-ui 패턴 (호스트 DOM 비접근 렌더)
  • 권한 모델: capability 선언과 최소 권한 (Chrome MV3식 사고)
  • untrusted JS 격리: SES / QuickJS-in-WASM, WASM 플러그인(Extism)
  • 원격 로딩: Module Federation·마이크로 프론트엔드, 버전 협상
  • 배포·신뢰성: 서명·검수·마켓플레이스, 그리고 AI 도구 계약(MCP)

Runnable에서 할 것

  • 데모 플러그인 하나를 Web Worker + 메시지 통신으로 격리 실행 PoC
  • capability 화이트리스트를 매니페스트에 추가하는 설계 스케치
  • 원격 URL에서 매니페스트를 불러오는 실험 (1st-party 한정)
  • "언제 이걸 도입할지" 판단 — YAGNI 기준으로 트레이드오프 문서화
Gate  서드파티 플러그인을 안전하게 받는다면 어떤 격리·권한·배포가 필요한지 설계하고, 핵심 한 가지를 PoC로 증명한다.
02 / CORE COMPETENCIES

가로지르는 6개 역량

레벨과 무관하게 계속 깊어져야 하는 축입니다. 단계가 올라갈수록 같은 역량을 더 높은 강도로 요구합니다.

경계 설계
host ↔ plugin contract

무엇을 노출하고 무엇을 숨길지. 플러그인 개발의 70%는 좋은 경계를 긋는 일.

상태·데이터 흐름
unidirectional flow

store·sideeffect·반응성. 플러그인이 앱 상태를 안전하게 읽고 쓰는 규율.

격리·보안
isolation & capability

신뢰할 수 없는 코드를 가정하기. 샌드박스·권한·CSP·XSS 표면 이해.

성능
lazy & off-main-thread

지연 로딩, 번들 분할, 무거운 작업의 worker 이전. 플러그인이 앱을 느리게 하지 않기.

버저닝·호환
semver & deprecation

계약을 깨지 않고 진화시키기. 구버전 플러그인을 살려두는 전략.

DX·배포
authoring & distribution

플러그인 작성자가 겪는 경험. 스캐폴딩·문서·예제·마켓·서명.

03 / BUILD LADDER

만들면서 배우는 6개 프로젝트

읽기만으로는 늘지 않습니다. 순서대로 직접 만들면 위 4단계를 자연히 통과합니다.

1
Hello-Chip
아무 동작 없는 chip 하나를 모서리에 띄운다. 매니페스트→레지스트리→렌더 전 과정 체득.
L1 · 경계 설계 입문
2
상태 반응 패널
현재 경로/시설 데이터를 보여주는 sidepanel. store 구독과 반응성.
L2 · 상태·데이터 흐름
3
토글 + 지연 로딩
사용자가 켜고 끄며, 켤 때만 동적 import 되는 플러그인. prefs 연동.
L2 · 성능
4
PluginContext SDK
플러그인에 주입할 공개 API 표면을 설계하고, 기존 플러그인을 그 위로 이전.
L3 · 경계 설계 · 버저닝
5
새 확장점 열기
호스트에 새 슬롯 타입을 추가해, 다른 사람이 거기에 꽂을 수 있게 한다.
L3 · DX·배포
6
Worker 격리 PoC
플러그인 로직을 Web Worker로 분리하고 메시지로 렌더 명령만 주고받는다.
L4 · 격리·보안 · 성능
04 / PITFALLS

초·중급에서 자주 빠지는 함정

대부분 "경계를 안 그어서" 생깁니다. 미리 알면 한 단계 빨리 통과합니다.

✗ 내부 직접 의존

플러그인이 features·entities를 직접 import. 호스트가 리팩터링하면 다 깨짐. → context 주입으로.

✗ 전부 신뢰

"내가 만든 거니까 괜찮아"로 권한·격리를 건너뜀. 서드파티를 받는 순간 재설계 비용 폭증.

✗ 동기 무거운 작업

메인 스레드에서 큰 계산. 플러그인 하나가 앱 전체를 멈춤. → worker/lazy로.

✗ 계약 없는 변경

호스트 API를 말없이 바꿔 기존 플러그인이 조용히 깨짐. → semver·deprecation 경로.

✗ 과설계

1st-party만 있는데 샌드박스·마켓까지 미리 구축. YAGNI — 필요해질 때 도입.

✗ DX 무시

작성 방법이 머릿속에만. 스캐폴딩·예제·문서 없으면 아무도(미래의 나 포함) 못 씀.

Runnable 실습 지점은 app/plugins-ext/ (types.ts · registry.ts · usePluginSurfaces.ts · sidewalk/explore 예제) 와 마운트 지점 app/widgets/map-shell/ui/MapOverlays.vue 기준입니다. 산업 맥락은 ②(TODO2)와 연결됩니다. 학습 순서·gate는 가이드라인이며, 본인 페이스에 맞게 조정하세요.
