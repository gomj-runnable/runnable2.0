Runnable · Frontend Lecture · 01

화면은 왜 알아서 바뀌는가
— 반응형(Reactivity)

현대 프론트엔드의 출발점은 단 하나의 질문입니다 — 데이터가 바뀌면 화면이 어떻게 따라오는가. 이 챕터는 Vue의 ref·reactive·computed·watch 가 그 일을 어떻게 자동화하는지, 그리고 그게 왜 이후 모든 패턴(MVVM·상태관리)의 토대가 되는지를 다룹니다.

01 / WHY

명령형 vs 선언형

반응형이 없던 시절엔, 데이터가 바뀔 때마다 화면을 사람이 직접 다시 그려야 했습니다.

명령형 — 직접 갱신 (옛 jQuery 식)

let count = 0
button.onclick = () => {
  count++
  // 데이터를 바꾼 뒤,
  // DOM 도 손으로 다시 써야 한다
  label.textContent = count
}

데이터와 화면을 두 번 관리. 갱신을 빠뜨리면 화면이 데이터와 어긋난다. 화면이 복잡해질수록 동기화 코드가 폭발한다.

선언형 — 반응형 (Vue)

const count = ref(0)
// 데이터만 바꾼다
button.onclick = () => count.value++

// 템플릿은 count 에 "묶여" 있어
// 값이 바뀌면 화면이 알아서 갱신
<span>{{ count }}</span>

데이터 하나만 관리하면 된다. "어떻게 갱신할지"가 아니라 "무엇을 보여줄지"만 선언한다. 동기화는 프레임워크의 몫.

02 / PRIMITIVES

반응형 4총사

Vue Composition API 의 반응형은 네 가지 도구로 거의 다 표현됩니다.

ref()

단일 값을 반응형으로. 값 접근·변경은 .value 로. 숫자·문자열·객체 무엇이든.

언제: 하나의 상태 조각

reactive()

객체 전체를 반응형으로. .value 없이 속성 접근. 중첩 객체까지 추적.

언제: 묶음 상태 객체

computed()

다른 반응형 값에서 파생되는 값. 의존 값이 바뀔 때만 다시 계산하고 캐싱한다.

언제: 계산된 결과

watch()

특정 반응형 값이 바뀌는 순간 부수효과 실행. API 호출·렌더링 트리거 등.

언제: 변화에 반응한 동작

핵심 구분: computed 는 "값"이고 watch 는 "동작"이다. "다른 값에서 새 값을 만든다"면 computed, "값이 바뀌면 무언가를 한다(네트워크·렌더링)"면 watch. 이 둘을 헷갈리면 불필요한 상태가 늘어난다.

03 / IN RUNNABLE

이 프로젝트에서의 반응형

Runnable 의 store 는 Nuxt 의 useState 위에 선 반응형 상태입니다 — ref 의 SSR 안전 버전.

// entities/route/model/useRouteInfoStore.ts
const routeInfos = useState('routeInfo.data', () => [])   // 반응형 상태
const isLoading  = useState('routeInfo.isLoading', () => false)

// features/route-info/api/useRouteInfoSideeffect.ts
watch(                                  // 상태가 바뀌는 순간
  [() => store.routeInfos.value, () => store.draftRouteInfos.value],
  () => renderRouteInfoMarkers(),        // 지도 마커를 다시 그린다
  { deep: true }
)

여기서 흐름은: 서버 응답 → store 갱신 → watch 감지 → 지도 재렌더. 컴포넌트는 store 값을 그냥 읽기만 하고, 값이 바뀌면 화면(과 지도)이 알아서 따라옵니다. 이 "알아서"가 반응형이고, 다음 챕터의 MVVM 은 이 토대 위에 세워집니다.

04 / MENTAL MODEL

의존성 추적 그래프로 상상하라

한 문장 멘탈 모델

반응형이란 "이 화면 조각이 어떤 데이터에 의존하는지" 를 프레임워크가 자동으로 기록해 두었다가, 그 데이터가 바뀌면 의존하던 조각만 콕 집어 다시 실행하는 시스템이다. 너는 그래프를 그릴 필요가 없다 — 값을 읽는 순간 그래프가 자동으로 그려진다.
