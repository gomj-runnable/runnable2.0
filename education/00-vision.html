Vision · 이 문서들이 향하는 곳

웹의 다음은
서비스의 개인화다

나머지 문서(①~⑥)는 전부 이 한 장의 미래를 향합니다. 코드를 보기 전에, 우리가 무엇을 믿고 무엇을 훈련하는지부터 좌표를 찍습니다 — 그래야 plugins-ext 의 작은 chip 하나를 만드는 일이 왜 큰 그림의 첫 벽돌인지 보입니다.

01 / THE FUTURE

개인화 웹 — 4개의 명제

"모두가 자기 메인 페이지를 갖고, 기능을 가져다 쓰거나 직접 구현한다"를 풀어쓰면 이렇게 됩니다.

1
메인 페이지는 한 회사의 산출물이 아니라, 내가 조립한 결과다

지금 우리는 회사가 정해준 화면을 소비합니다. 개인화 웹에서는 각자가 자기 화면을 구성합니다 — 필요한 기능을 골라 꽂고, 안 쓰는 건 뺍니다.

2
기능은 페이지가 아니라 모듈이다

"날씨", "지도 경로", "할 일"이 각각 독립적으로 가져다 쓸 수 있는 플러그인 단위가 됩니다. 앱과 앱의 경계가 흐려지고, 기능과 기능의 조합이 전면에 옵니다.

3
쓰거나, 직접 구현하거나 — 둘 다 1급 시민이다

남이 만든 모듈을 설치해 쓰는 길과, 내가 만든 모듈을 같은 자리에 꽂는 길이 같은 계약 위에 있습니다. 소비자와 제작자의 거리가 가까워집니다.

4
이 모든 것을 떠받치는 건 '판(host)'이다

모듈이 꽂힐 슬롯·계약·생명주기·권한을 정의하는 그릇이 있어야 조립이 성립합니다. 이 판을 설계하는 사람이 개인화 웹의 핵심 직군입니다.

02 / THE SHIFT

네가 되려는 사람

플러그인을 쓰는 개발자는 많습니다. 드문 건 플러그인을 받아주는 판을 설계하는 개발자입니다.

흔한 쪽 · 소비자

기능을 만드는 개발자

  • 주어진 프레임워크 안에서 화면·기능을 구현
  • "이 버튼을 누르면 무엇이 되는가"에 집중
  • 호스트가 정해준 규칙을 따른다
  • 대체 가능성이 높고 경쟁이 치열

드문 쪽 · 플랫폼

판을 만드는 개발자

  • 경계를 긋는다 — 무엇을 노출하고 무엇을 숨길지
  • "남이 무엇을 꽂을 수 있게 할 것인가"에 집중
  • 호스트의 규칙 자체를 설계한다 (슬롯·계약·권한)
  • 희소하고, 개인화 웹이 정확히 요구하는 역량
④ 로드맵의 L1~L4 사다리는 결국 이 화살표 하나를 건너는 과정입니다 — 왼쪽(소비자)에서 오른쪽(판 설계자)으로. 각 레벨의 gate가 그 이동의 눈금입니다.
03 / WHY RUNNABLE

왜 이 프로젝트가 훈련장인가

개인화 웹의 큰 개념들은 추상적입니다. Runnable의 plugins-ext 는 그 개념들을 지금 손으로 만질 수 있는 최소 형태로 이미 갖고 있습니다. 미래의 큰 단어 ↔ 지금의 작은 코드 매핑입니다.

모듈 단위 기능
→ 지금 있는 것

plugin 폴더 + plugin.manifest.ts 가 곧 한 개의 모듈. 지도 위 chip/패널이 그 산출물.

조립되는 판(host)
→ 지금 있는 것

registry.ts + PluginSurfaceHost.vue 가 슬롯에 모듈을 자동 주입하는 호스트.

꽂는 자리(슬롯)
→ 지금 있는 것

chip · sidepanel · dashboard · popup 4종 슬롯 + chip의 8방향 앵커.

설치/제거
→ ⑤에서 만든다

usePluginPrefs 의 on/off 를 '설치'로 확장, 동적 import 로 0비용 미설치.

안정적 계약(SDK)
→ ④ L3에서 만든다

플러그인이 내부를 몰라도 동작하는 PluginContext. 아직 없음 — 네가 설계할 것.

격리·권한·원격
→ ④ L4 · ⑥ 한계

서드파티를 받을 때 필요. 1st-party뿐이면 과설계(YAGNI). ⑥에서 왜 아직 어려운지.

핵심: 큰 미래를 한 번에 짓지 않는다. Runnable에서 "모듈 → 호스트 → 슬롯 → 설치 → 계약 → 격리"를 작게 한 칸씩 만들어 보는 것 — 그게 개인화 웹을 짓는 근육을 기르는 가장 빠른 길입니다.
04 / THE MAP

여기서 어디로

이 비전을 코드로 옮기는 순서입니다. 낯선 용어가 나오면 ①로 돌아가세요.

01사전 지식 — 런타임·모듈·Vue·Nuxt·플러그인 어휘. 막히면 찾아보는 용어집. 02app/ 구조 — 판이 올라앉은 FSD 5층 구조와 의존 방향. 03플러그인 진화 — 업계가 같은 미래를 향해 어떻게 움직여 왔나(4세대). 04개발자 로드맵 — 소비자 → 판 설계자로 가는 L1~L4 사다리. 05온디맨드 설치 — '설치' 버튼의 실체. 첫 실전 기능. 06한계와 미래 — 이 꿈이 웹 전체 규모로는 왜 아직 불가능한가. 07학습 로그 — 네가 실제로 통과한 gate와 만든 것을 기록하는 곳.
QUIZ / 이해도 체크

학습 완료 퀴즈

이 비전 문서의 4개 명제와 역할 전환을 제대로 짚었는지 4문항으로 확인합니다.

  1. 이 문서가 말하는 '개인화 웹'에서 메인 페이지는 무엇인가?

    • a) 한 회사가 정해준 화면을 그대로 소비하는 것
    • b) 내가 필요한 기능을 골라 꽂고 안 쓰는 건 빼서 조립한 결과
    • c) 검색 엔진이 자동 생성해 주는 화면
    • d) 디자이너만 수정할 수 있는 고정 레이아웃

  2. 이 비전이 "되려는 사람"으로 지목한, 드물고 희소한 역할은?

    • a) 주어진 프레임워크 안에서 기능만 구현하는 소비자 개발자
    • b) 호스트가 정해준 규칙을 빠르게 따르는 개발자
    • c) 슬롯·계약·권한 등 규칙 자체를 설계하는 '판을 만드는 개발자'
    • d) 플러그인을 가장 많이 설치해 본 사용자

  3. 개인화 웹의 모든 조립을 떠받치는 핵심(4번째 명제)은 무엇인가?

    • a) 더 빠른 인터넷 회선
    • b) 슬롯·계약·생명주기·권한을 정의하는 '판(host)'
    • c) 더 많은 광고 수익
    • d) 단일 회사의 통합 디자인 시스템

  4. Runnable의 plugins-ext 가 이 비전의 훈련장으로 적합한 이유는?

    • a) 큰 미래를 한 번에 완성된 형태로 이미 구현해 두었기 때문
    • b) 추상적 개념을 지금 손으로 만질 수 있는 최소 형태로 갖고 있어, 한 칸씩 만들며 근육을 기를 수 있기 때문
    • c) 서드파티 격리·권한·원격까지 모두 완성돼 있기 때문
    • d) 플러그인을 쓰는 법만 가르치기 때문
