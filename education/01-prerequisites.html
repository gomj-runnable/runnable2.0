①~④를 이해하려면 몇 가지 개념을 먼저 알아야 합니다. 깊이 파고들 필요는 없고, "이 단어가 무슨 뜻이고, 왜 거기서 쓰이는지" 정도면 충분합니다. 각 묶음 끝에 그 지식이 어느 문서를 여는 열쇠인지 표시해 두었습니다. 모르는 묶음만 골라 읽으세요.

어떻게 읽을까

0이 문서(사전 지식) 에서 낯선 묶음만 훑기 — 용어 감 잡기
1묶음 F·G(아키텍처·플러그인 어휘) → ① app/ 구조 가 읽힘
2묶음 G(플러그인 어휘) → ② 진화, ③ 로드맵
3묶음 A·B·C·D(런타임·모듈·Vue·Nuxt) → ④ 온디맨드 설치 의 코드가 이해됨
01 / KNOWLEDGE CLUSTERS

7개 지식 묶음

각 카드는 용어 한 줄 정의입니다. 외우지 말고, 문서를 읽다 막히면 돌아와 찾아보세요.

A 브라우저 런타임 & 성능 → ④ 이해의 핵심
메인 스레드

브라우저가 JS 실행·렌더를 처리하는 단일 흐름. 여기서 무거운 일을 하면 화면이 멈춤(버벅임).

로드 4단계

다운로드 → 파싱 → 컴파일/실행 → 메모리 적재. "성능 비용"은 이 4가지의 합. 안 받으면 4개 다 0.

힙(heap) 메모리

실행 중 객체가 올라가는 공간. 컴포넌트 인스턴스·구독이 여기 쌓임. "메모리에 올라온다"의 그곳.

DevTools

Network 탭(무엇을 받았나)·Performance 탭(어디서 시간 썼나). ④의 효과를 측정하는 도구.

B 모듈 & 번들 → ④
ES Module import

파일을 다른 파일에서 가져오는 표준. 최상단 정적 import 는 항상 함께 로드됨.

동적 import()

함수처럼 호출하는 import. 호출하는 순간에만 로드. ④ "설치"의 기술적 정체.

번들러 / Vite

여러 파일을 브라우저용으로 묶는 도구. 정적은 합치고, 동적 import 는 쪼갬.

청크 / 코드 스플리팅

쪼개진 JS 조각이 청크. 동적 import 마다 별도 청크 → 필요할 때만 받음.

모듈 캐시

한 번 받은 모듈은 메모리에 남음. 그래서 "제거해도 코드는 완전히 안 내려감"(④의 함정).

C Vue 3 (Composition API) → ①④
컴포넌트 .vue

화면 한 조각(템플릿+로직+스타일). 플러그인은 결국 이 컴포넌트.

반응성 ref/computed

값이 바뀌면 화면이 자동 갱신. computed 는 다른 값에서 파생된 값.

컴포저블 use*

로직을 함수로 묶어 재사용. store·sideeffect·facade 가 전부 이 형태.

defineAsyncComponent

로더 함수를 받아 렌더 시점에 로드하는 컴포넌트. ④의 핵심 도구.

<component :is>

어떤 컴포넌트를 그릴지 동적으로 정함. 호스트가 슬롯에 플러그인을 꽂는 방법.

D Nuxt 4 → ①④
파일 기반 라우팅

pages/ 의 파일이 곧 URL. 페이지는 자동으로 라우트 단위 코드 분리됨(=페이지 이동 시 로드).

자동 import

ref·useState 등을 import 없이 사용. 그래서 코드에 import 줄이 적게 보임.

useState

SSR-안전한 전역 공유 상태. store 가 이 위에 세워짐(plugin-prefs 등).

$fetch

서버 API 호출 헬퍼. /api/me/feature-prefs 같은 설치 상태 저장에 쓰임.

<ClientOnly>

클라이언트에서만 렌더. 설치형처럼 브라우저 전용 동작의 하이드레이션 문제를 피함.

E TypeScript 기초 → 전부
interface / type

객체의 모양(필드·타입)을 정의. PluginManifest 가 대표 예시.

제네릭 <T>

타입을 매개변수로 받음. Promise<{ default: Component }> 처럼.

Promise / async

나중에 끝나는 작업의 결과 그릇. 동적 import 는 Promise 를 돌려줌 → await 로 기다림.

F 아키텍처 어휘 (FSD) → ①
FSD 레이어

pages → widgets → features → entities → shared 5층. 위가 아래만 의존(단방향).

슬라이스 / 세그먼트

레이어 안의 도메인 폴더(슬라이스)와 그 안의 api/model/lib/ui(세그먼트).

의존 방향

"누가 누구를 import 하는가"의 규칙. 역방향·교차 의존 금지가 핵심.

Facade

여러 조각을 단일 창구로 묶어 호출부를 단순화. useRouteMapFacade.

G 플러그인 시스템 어휘 → ②③④
호스트 / 플러그인

확장을 받아주는 본체(host)와, 거기 끼워지는 기능(plugin).

매니페스트

플러그인의 자기소개 메타데이터(id·슬롯·위치·기본값). PluginManifest.

슬롯 / 확장점

호스트가 열어둔 자리(chip·sidepanel·dashboard·popup). 플러그인이 여기에 꽂힘.

레지스트리

플러그인 목록을 모아둔 곳(registry.ts). 호스트가 여기서 읽어 렌더.

생명주기 / lazy

등록 → (지연)로드 → 마운트 → 해제. lazy = 필요할 때만 로드.

샌드박스 / 권한

신뢰 못 할 코드를 격리(iframe·Worker)하고 능력만 허가. ②③의 상위 개념.

이 문서는 ①~④를 읽기 위한 최소 토대만 다룹니다. 더 깊은 내용은 각 공식 문서(Vue·Nuxt·Vite·TypeScript)와 프로젝트 위키(docs/wiki/2-Architecture.md)를 참고하세요. 막히면 언제든 여기로 돌아와 용어를 찾으세요.
